## Overview

A writer planning a manuscript or a body of research can browse the Organizer only as one wrapping list of cards for one folder, in one order. They cannot lay the documents out by a field (scenes by plotline against status, evidence by suspect), see which documents have no value for it, or change a field without opening each document in the sidebar. This feature makes the Organizer able to lay its cards out as a grid: a Rows picker and a Columns picker choose a field (columns may also be document order), the source can be the selected folder, the folder and its descendants, or a smart folder, and each card sits in the cell its field values name. Dragging a card to another cell sets those fields, a "None" row or column catches documents with no value, and a phone shows grouped lists instead of a matrix. Writers can then save the arrangement under a name for the project and switch between saved arrangements, and a project type or module can start a new project with some. Today's Organizer stays the default arrangement, and nothing changes in compile, export or cross-folder moves. Android and paired-device support are claimed only after a recorded run.

## Goals

- A writer can choose a row field and a column field (or document order) in the Organizer, over a folder's direct children, its descendants flattened, or a smart folder, and see every card in the cell its values name, with documents that have no value in a "None" row or column and stored values not on the field's list in "Other values".
- A writer can drag a card to another cell to set, clear or move one value of an axis field, with a refusal or a failed write shown in text and never shown as done.
- A writer can use the grid by keyboard alone, with row and column structure exposed to assistive technology, and on a phone sees grouped lists with no card hidden.
- A writer can save, apply, rename and delete named arrangements for the project, shared by every device, with the last-used one remembered per device, and a new project can start with arrangements from its project type or a module.
- Existing projects see today's Organizer unchanged as the default arrangement, no card past the card cap is silently omitted, and the grid is verified on a physical Pixel 7 Pro and a paired device with every unmeasured path listed.

## Non-goals

- Derived, read-only entity-mention rows; creating a document from an empty cell; a date or in-world-order axis, a Timeline comparison, a richer date model; text, number, date or boolean axes; per-cell stored order; a "Move to..." menu; structure packs or a beats overlay (product FR-189).
- Saved filters in an arrangement, and any change to how filters work or reset.
- A new paired-device limit switch, a writing-log entry or a revision for a drag, and any change to compile, export or cross-folder moves (those stay tree operations).
- A new work-area view or a new top-level tab; the grid is a layout of the Organizer.
- Editing a project type's arrangements in the Project Type Manager beyond what OQ-12 settles, and re-applying a type or module to an existing project.

## User stories

- US-1: As a writer planning a manuscript or a body of research, I want to lay my documents out in the Organizer in rows and columns by a field or by document order, so that I can see how they relate along the dimension I care about. (Product US-50.)
- US-2: As a writer, I want to drag a card to another row or column to change that field, and be told when it is refused or fails, so that I can reorganise without opening each document. (Product US-50.)
- US-3: As a writer, I want to save an arrangement under a name for the project and switch between saved arrangements, and have a new project of a research-minded type start with some, so that I do not re-pick rows and columns each time. (Product US-50, FR-183, FR-184.)
- US-4: As a writer on a phone, I want to see the grid as grouped lists in which no card is hidden, so that the Organizer stays usable on a small screen. (Product FR-186.)
- US-5: As a writer who uses a keyboard or a screen reader, I want to move between cells, open a card and move it to another cell without a pointer, so that the grid is as usable as it is by mouse. (Product FR-187.)
