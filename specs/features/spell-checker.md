## Overview

A writer on deadline types a misspelling and nothing in GetWrite marks it, and the browser's, Electron's or the Android keyboard's own checker, where it shows at all, shows differently on each platform and cannot be told about a character name or an invented term. This feature adds a spell checker that is part of GetWrite: the same unknown words underlined in the editor body on the web, on desktop and on Android; a menu on a flagged word that replaces it from suggestions, ignores it, or adds it to the project's own word list; entity names and aliases never flagged; a view and remove screen for the two lists; and one switch in App Settings that turns the checker on or off for the whole app at once. It does not rely on any native checker. Before any of that is built, the feature measures the two candidate engines on all three platforms, and halts for the owner to choose.

## Goals

- The owner chooses the engine from recorded numbers: load time (cold and warm), suggestion time, download size, memory and long-document check time for `nspell` with `dictionary-en` and for `harper.js`, on web, desktop and Android, plus whether `spellcheck="false"` suppresses native underlines on each platform.
- A word in the editor body that is in none of the dictionary, the project word list, the project ignore list, or the project's entity names and aliases is underlined the same way on web, desktop and Android, with no native underline in the editor on any of them.
- A writer can replace a flagged word from suggestions, ignore it, or add it to the project dictionary from one menu, and the underline goes away in every open editor at once.
- The checker is on by default for everyone, including existing users, and a single App Settings switch turns it on or off for every open project without reopening it.
- A writer can see and remove every word in the project word list and the ignore list, and the licence notice for what ships is in the web, desktop and native outputs.

## Non-goals

- The cross-project user word list, its three platform stores and its App Settings section (Feature 96); "Add to my dictionary".
- Languages other than English, a language setting, or the UK dictionary (OQ-121).
- Grammar, style or punctuation checking.
- Checking the Markdown source view, titles, metadata fields, search boxes or any text but the editor body (OQ-123).
- Relying on or configuring the browser's, Electron's or Android's built-in checker, other than setting `spellcheck="false"`.
- Adding a word from the Spelling tab (the tab views and removes; adding happens from the editor menu).
- Writing any engine-dependent code before the owner's engine choice.
- A performance limit chosen in advance; the owner sets any limit after Part 0 (OQ-129).

## User stories

- US-1: As a writer on deadline, I want to see a real misspelling in my text underlined the same way on the web, on desktop and on Android and to replace it from suggestions, so that I catch it without leaving the editor. (Product US-33.)
- US-2: As a writer on deadline, I want to tell the checker to ignore a flagged word or to add it to my project's own dictionary, so that a name or term I use on purpose is not flagged again and again. (Product US-33.)
- US-3: As a writer on deadline, I want to turn the spell checker on and off for the whole app, with the change applied at once to every open project, so that I can have it out of the way without reopening anything. (Product US-33.)
- US-4: As a writer on deadline, I want to see and remove the words in my project's word list and ignore list, so that a mistaken Add or Ignore does not stay until I edit `project.json` by hand. (Product US-33; F94-4 option d.)
- US-5: As a product owner choosing the checker's engine, I want to have both candidate engines measured on web, desktop and Android before one is fixed, so that the choice rests on numbers and not on a guess. (Product US-33; FR-78 "not final until a spike has measured".)
- US-6: As a maintainer shipping GetWrite, I want to have the licence notices for the spell-check packages that ship in every build output, so that GetWrite meets the licences it ships under. (Product US-33; F94-5.)
