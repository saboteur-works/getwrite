## Overview

A writer researching a legend, a folktale or an event with several accounts keeps each telling as a separate document and compares them by switching back and forth or by pasting them into a spreadsheet, where the text is lost. GetWrite already holds Sources with a body, attachments, a subtype and fields, and folders with a subtype and fields, but it has no way to say "these Sources are the tellings of one story", to tag each telling with motifs and tale types from a vocabulary the writer keeps, or to read two tellings next to each other. This feature adds a switchable first-party module, off by default, that treats a folder with the subtype Narrative as one story and the Sources inside it with the subtype Variant as its tellings, lets a writer keep a motif list and a tale-type list as their own multiselect fields and tag each variant from them, and adds one project-scope Work Area tab that lists a narrative's variants with teller, date, place, motifs and tale types and opens two or more of them side by side in a read-only comparison. A writer comparing witnesses or reports uses the same tab with no tags set. No new resource type or record kind is added, nothing is compiled or indexed differently, and Android, paired-device and phone claims are made only after a recorded run.

## Goals

- A writer can switch the folklore module on in Project Settings > Modules, keep the tellings of one story as the Variant Sources of a Narrative folder, and see them in one tab with teller, date, place, motifs and tale types, opening any of them in the editor.
- A writer can keep a motif list and a tale-type list as the project's own multiselect fields, tag a variant with several of each, and see a tag that is not in the list shown and marked, never rewritten.
- A writer can read two or more variants of one narrative side by side, each with its fields above its text and each column scrolling on its own, with an unreadable variant, a locked project and an audio-only variant each shown as what they are, never as empty text, and with no write on open or close.
- The module is off for every project with no entry for it, seeds nothing, depends on no other module, keeps all data when switched off, and changes nothing in compile, export, goals or indexing.
- Every figure and claim is backed by a recorded run: the column limit from a run on long text, and Android and paired-device parity from a device run, with every path not run listed as not verified.

## Non-goals

- Smart-folder, Organizer-grid and search use of motifs and tale types as a feature (Feature 111), the built-in Folklore collection project type (Feature 112), the phone layout of the comparison (Feature 113), CSV import of a list (Feature 114), and passage-level motif marks (Feature 115).
- A text diff (alignment or word-change highlighting), a bundled or preloaded published index (ATU, Thompson or other), a new resource type or record kind, comparison of the writer's own drafts (Alternates), variants on a map or timeline, and a shared or public folklore database.
- Cross-narrative comparison, a variant in two narratives, a typed date, and any compile or export of a narrative or a comparison.
- Tags on a narrative folder, on a passage or on an attachment; a tag value that is not a string from the list.
- Editing a variant inside the comparison, and a collaborative or shared selection.
- Any change to the Sources module, the claim ledger, Document status or `config.statuses`.

## User stories

- US-1: As a writer researching a legend or folktale, I want to keep the different tellings of one story together as variants, each with who told it, when and where, so that I can see them as one set without switching between documents. (Product US-51.)
- US-2: As a writer researching a legend or folktale, I want to tag each variant with motifs and tale types from lists I keep myself, so that I can see which elements recur across stories without a spreadsheet. (Product US-51.)
- US-3: As a writer researching a legend or folktale, I want to read two or more variants side by side, so that I can see what changed between tellings. (Product US-51.)
- US-4: As a true-crime or nonfiction writer comparing accounts of one event, I want to read two or more accounts side by side, each with who gave it, when and where, and no motifs set, so that I can see where the accounts agree and differ. (Product US-52.)
- US-5: As a writer who does not research folklore, I want to leave the module off until I switch it on and to keep my data when I switch it off, so that I never see it unless I want it and never lose work by turning it off. (Product FR-190.)
