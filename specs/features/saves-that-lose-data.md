## Overview

Four independent defects share one shape: a write or a read drops data a writer had saved. Saving Body Text Styles erases the Heading Styles saved before it. Choosing a Status after typing stores a word count of 0, and the Data view's By status figure reads 0 until a reload. Deleting a resource leaves the built-in Point of View reference that another resource held to it. The Start Page's Package view lists and compiles only the resources that sit inside a folder. This feature corrects these four behaviours and adds no capability. It can be cut by defect; the four parts do not depend on each other.

## Goals

- Saving Body Text Styles leaves the saved Heading Styles unchanged, and saving Heading Styles leaves the saved Body Text Styles unchanged, on the HTTP and native paths alike.
- Choosing a Status (or any other sidecar field) after typing leaves the resource's stored `wordCount` at the value the last canonical save wrote, and the Data view's By status figures agree with the footer without a reload.
- Deleting a resource clears the built-in Point of View reference held to it, in every project including those whose metadata schema was never edited, and restoring the resource re-links it.
- The Start Page's Package view lists, and compiles, every resource of a project, including those outside any folder.
- Every cause that is a HYPOTHESIS or a READ is tested before its fix, and the fix is shown to turn that test green.

## User stories

- US-1: As a writer on deadline, I want to save new settings and edits without anything I saved earlier being erased so that a save never costs me earlier work. (Product spec US-9.)
- US-2: As a writer on deadline, I want to have a reference field such as Point of View cleared when its target is deleted, and re-linked when the target is restored, so that my metadata never points at a document that no longer exists. (Product spec US-14.)
- US-3: As a writer on deadline, I want to see every resource in a project when I package it from the Start Page so that the file I compile is the whole project. (Product spec US-15.)
- US-4: As a writer on deadline, I want to read the words per status in the Data view as I wrote them so that the roll-up matches the footer. (Product spec US-19.)
