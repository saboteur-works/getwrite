## Overview

Three gaps in compile and export are closed together. First, a writer who wants the same resources left out of every compile or export of a project has to untick them each time; the dialogs start from nothing saved. Second, a writer cannot attach a note to the exact words it concerns, so reminders, questions and evidence live apart from the passage and drift away from it. Third, on the Android app a PDF compile fails with a Node-only error, and the Start Page hides that error behind a generic message. This feature adds per-project saved defaults in the compile and export dialogs that a single run can override, adds plain-text annotations that follow their passage and are found by search, and makes the existing PDF compile work on Android and show its real error when it fails. Each part starts from a failing test or recorded reproduction, because several statements above are readings.

## Goals

- Compile and export dialogs start from the project's saved defaults, show each default in effect, let the writer override it for one run without changing the saved default, and let the writer change the saved default.
- A writer can attach a plain-text note to a passage of a text resource, see it beside the passage in a panel at every screen width, edit or delete it, find it by search, and never lose it silently when its passage goes.
- Annotations never change compile or export output, shown by a test that compares annotated and unannotated documents.
- A PDF compiled in the Android app contains the selected resources, with the server and desktop path unchanged, and a PDF failure shows the real error message.
- Every new config setter and annotation write works on the native (Android) transport as on HTTP, with the same validation.

## Non-goals

- Seeding saved defaults from a project type or a module (OQ-132 (b)); a later feature may add an optional seed key.
- Margin notes beside the text (OQ-135); jumping from a search hit to the annotated passage (OQ-136).
- Annotations on image and audio resources (FR-90 of the product spec); no add control is offered there.
- Rich-text annotation bodies; annotations as collaborator comments; importing DOCX comments as annotations.
- Citations, excerpts, claim ledger or any `target` on an annotation: the sidecar shape does not carry a `target` field in this feature.
- Any change to the server or desktop PDF render path, to PDF fonts, or to DOCX, text or Markdown compile output.
- Making the Android PDF fonts embed by any change beyond what the part 3 test shows is needed; FR-92's check is recorded verification only.

## User stories

- US-1: As a writer compiling or exporting, I want to have the compile and export dialogs start from defaults saved for my project, such as what is included and what is left out, and to change them for one run, so that I do not repeat the same choices each time and can still make an exception when I need one. (Product spec US-36.)
- US-2: As a writer, I want to attach a note to a passage of my text, a note to myself that sits beside the passage and stays with it as I edit, so that I can record a reminder, a question or a piece of evidence against the exact words it concerns. (Product spec US-37.)
- US-3: As a writer who works on an Android phone or tablet, I want to compile a PDF in the Android app and get the same fonts as on desktop, so that PDF output is not limited to the web and desktop versions. (Product spec US-38.)

## Open questions

All sixteen questions were answered by the owner at Gate 3 on 2026-11-04 and are folded into the requirements named in each entry. They are kept here as the record. None remains open.

- OQ-1 (RESOLVED, Gate 3, 2026-11-04): Does a saved default cover more than excluded resource ids? Answer: a saved default holds only `{ excludedResourceIds: string[] }`; headers, format and name stay per-run (`CompilePreviewModal.tsx:88-90`). Applied in FR-1.
- OQ-2 (RESOLVED, Gate 3, 2026-11-04): What is the maximum number of excluded ids a setter accepts? Answer: at most 5000, UUID-checked and deduped; above the cap the setter refuses with a message and stores nothing (reject, never truncate), consistent with the spelling-list cap. Applied in FR-2.
- OQ-3 (RESOLVED, Gate 3, 2026-11-04): When saved defaults cannot be read at dialog open, may the writer still compile? Answer: the dialog shows a visible failure notice with Retry, opens with all resources selected and says the saved defaults are not applied; compile remains allowed; "Save as default" is disabled while the read has failed; a locked-access error is rethrown to the existing locked path. Applied in FR-5.
- OQ-4 (RESOLVED, Gate 3, 2026-11-04): Does entity-scoped compile apply saved exclusions? Answer: no; it applies none and does not render the saved-defaults UI (`CompilePreviewModal.tsx:142-143, 227-228`). Applied in FR-6.
- OQ-5 (RESOLVED, Gate 3, 2026-11-04): Does the Start Page compile path apply saved defaults? Answer: yes if its project list entry carries `config`; the first task reads `listProjectsCore` entries and `ProjectListEntrySchema` to find out; if not carried, no per-project fetch is added and the gap is recorded, not silently ignored. Applied in FR-6.
- OQ-6 (RESOLVED, Gate 3, 2026-11-04): Which tool extracts and validates PDF text in tests? Answer: add `pdfjs-dist` as a devDependency (owner approved under `docs/standards/package-selection.md`); fallback if it cannot run in the node test project: compare react-pdf's rendered element tree for FR-8, real extraction only for FR-26. Applied in FR-8 and FR-26.
- OQ-7 (RESOLVED, Gate 3, 2026-11-04): What are the annotation limits? Answer: body 1 to 5000 characters, saved quote up to 500, at most 500 annotations per resource; over a limit is refused with a message naming the limit, never truncated. Applied in FR-11.
- OQ-8 (RESOLVED, Gate 3, 2026-11-04): Does text typed at an annotation's edge join it? Answer: no; the `annotation` mark is `inclusive: false`, text typed at either edge stays outside, and both edges are tested. Applied in FR-13.
- OQ-9 (RESOLVED, Gate 3, 2026-11-04): Where does the annotations panel sit? Answer: a drawer or panel opened from an editor toolbar button, working at every width, focus returning to the opener; unless the first Part 2 UI task finds the metadata sidebar is already visible at phone width, in which case a section in `MetadataSidebar.tsx`; the task records which and why. Applied in FR-14.
- OQ-10 (RESOLVED, Gate 3, 2026-11-04): Does re-attach update the quote? Answer: yes; `quote` becomes the newly selected text and `updatedAt` is bumped; the original quote is not kept. Applied in FR-16.
- OQ-11 (RESOLVED, Gate 3, 2026-11-04): Is a body-less mark removed at every load or only on restore? Answer: only on revision restore (product FR-86); at ordinary load it is inert (not shown, does not break the editor) and the document is not rewritten. Applied in FR-17 and FR-18.
- OQ-12 (RESOLVED, Gate 3, 2026-11-04): How is a cut told from a copy, and what does a cross-resource cut-and-paste do? Answer: within one resource, cut-and-paste keeps the annotation (same id) and copy-paste creates a new id with a copied body; cut vs copy is told apart by recording the last clipboard operation from the editor's `cut`/`copy` DOM handlers (ids and source resource id), proven by a test in the first task. Cross-resource cut-and-paste: the target gets a NEW id and a copy of the body; the source's annotation becomes detached (its mark left with the cut text), never deleted automatically. Annotation ids are never shared between resources. Applied in FR-19.
- OQ-13 (RESOLVED, Gate 3, 2026-11-04): How does search reach annotation bodies? Answer: bodies are indexed in `indexer-queue.ts`'s `runTask` with the text, under a separate term source so a hit's snippet is labelled "Note:"; an annotation write enqueues an index task; `reindex` keeps them. Evidence: `execute-search.ts:192,224` takes candidates from the inverted index, so a body-only match is not found today. Applied in FR-20.
- OQ-14 (RESOLVED, Gate 3, 2026-11-04): Do annotations travel when a resource is copied, duplicated or templated? Answer: copying or duplicating copies annotations with NEW ids, remapped in both the sidecar array and the document marks (`copyResourceCore` spreads the whole sidecar, `resource-crud-core.ts:316-317`; check `duplicateResource` in `resource-templates.ts:473` too); templates carry no annotations (plain text; `saveResourceTemplateFromResource` ~984-1052); test it. Applied in FR-21.
- OQ-15 (RESOLVED, Gate 3, 2026-11-04): Can the browser-build failure be reproduced in Vitest? Answer: attempt it by resolving `@react-pdf/renderer` to its browser build for that test (alias or conditions; `vitest.config.ts:43-59` sets none today); not yet run; the spec's fallback stays. Applied in FR-24.
- OQ-16 (RESOLVED, Gate 3, 2026-11-04): Are the other three Start Page catches in scope? Answer: yes; fix all four catches that discard the error, PDF, DOCX, Markdown and text (`StartPage.tsx:660-661, 675-676, 697-701, 713-717`), showing `err instanceof Error ? err.message : String(err)` like `AppShell.tsx:1335`; extend the FR-28 test to all four.
