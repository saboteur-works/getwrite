## Overview

A writer gathering evidence for nonfiction, true crime or folklore can keep a Source (Feature 102) but can reach it only through the resource tree and the metadata sidebar, cannot see an image or hear audio that is attached to it, cannot say where in a Source a passage sits, cannot tie a passage of their own text to a Source, and cannot choose Source in a query's Type filter. This feature gives them a project-scope Sources view listing every Source with its name, subtype and attachment count; an attachments section with image preview and audio playback; excerpts of a Source with an optional-typed locator; citations that tie a passage to a Source, an excerpt, an attachment and a locator through annotations; and "source" in the Type filter. It also gives a maintainer one internal first-party registry, with the Sources module as its first user, a per-project module switch in a new `config.modules`, and one shared derived-index rebuild used by the three importers and `reindex` (which then rebuilds annotation search too). The work is delivered in waves: the registry seam and a minimal Sources view first, then an owner checkpoint, then media, excerpts, citations and the Type filter.

## Goals

- A writer can open a Sources view, see every Source with its name, subtype and attachment count, and open one in the editor; with the module switched off the interface is not offered, the data is untouched and indexing for it stops.
- A writer can add, remove, replace and reorder attachments in the view, see an image and play audio on every platform where Sources core runs, and lose nothing the existing Trash rules would not already lose.
- A writer can mark an excerpt of a Source with a locator, tie a passage of their own text to a Source (and optionally an excerpt, attachment and locator), and see a citation whose Source is gone shown as pointing at something missing, never hidden or deleted.
- A writer can choose Source in a query's Type filter; the three importers and `reindex` rebuild the derived indexes from one shared list, and `reindex` makes annotation bodies searchable again.
- A maintainer can add a first-party module through one internal build-time registry, with no change in behaviour for any existing view, flag, compile format or setting, and with the Electron worker typecheck and build and the CLI build still green.

## Non-goals

- Any generic module storage channel (survey Shape B), runtime or third-party module loading, a permission model, an importer contribution kind, `@gw/core` extraction, a module-contributed resource type or Trash kind, and a project-type key that names modules (product FR-125, FR-129, FR-131, FR-135).
- Moving the eight existing views, seven flags or four compile formats into the registry, except the Trash conversion of FR-10.
- Per-project switching of editor schema extensions (OQ-170, open and not needed).
- Linking a Source to an entity, a where-cited index, citations in compile or export, a bibliography or footnotes, claim handling, and templates from or to a Source (product FR-124, FR-138, FR-139; OQ-162, OQ-168).
- A sixth paired-device limit switch, `appliesToTypes`, annotations on image or audio resources (product FR-90, FR-132, FR-134).
- Sidecar-key lifecycle and text-bodied-predicate refactors (OQ-160).

## User stories

- US-1: As a writer gathering evidence for nonfiction, true crime or folklore, I want to open a place in the app that lists my Sources and shows each Source's attachments, so that I work with my sources directly and not by hunting through the resource tree and the metadata sidebar. (Product US-41.)
- US-2: As a writer working from a Source, I want to mark an excerpt of it and record where it sits (a page, a timestamp, or another locator), so that I can find the passage again and say exactly where it came from. (Product US-42.)
- US-3: As a writer, I want to select a passage in my text and tie it to a Source, or to one of its excerpts, so that the passage shows what it rests on. (Product US-43.)
- US-4: As a maintainer adding a first-party module to GetWrite, I want to register what a module adds to the app in one internal place, built with the Sources module as its first user, so that a later module does not have to edit each large component by hand and the registry's shape comes from a real consumer. (Product US-44.)
- US-5: As a writer, I want to choose Source in the Type filter of a query, so that I can find my Sources and build a smart folder of them. (Product US-45.)
