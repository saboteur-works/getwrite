### Task 2: Throwaway metric stand-ins and timed benchmark harness
**What:** Write three minimal, non-product metric functions (dialogue ratio, average sentence length, top repeated words) and a Vitest harness that times each individually and combined at each of the three fixture sizes, with enough repetitions to report a stable number.
**Files:** `frontend/tests/proseDiagnosticsBenchmark.test.ts` (new)
**Done when:** the file's own header docblock states, in these or clearer words, that its three metric functions are throwaway cost stand-ins for this benchmark only and are **not** Feature 62's eventual implementations (mirrors this list's own notice above); `dialogueRatioStandin` computes a simple quoted-speech line/character ratio (count characters inside `"..."`/`"..."`-style quote pairs — including curly quotes, since the fixture may use them — divided by total characters); `averageSentenceLengthStandin` computes a simple sentence-boundary split (split on `/[.!?]+\s+/`-style boundaries, average words per resulting sentence); `topRepeatedWordsStandin` computes a simple lowercase word-frequency count and returns the top N; each function is a pure function taking only the text and returning a plain result, with no import from `src/lib/models/` or any product module; the harness times each function individually via `performance.now()` at each of the three fixture sizes, then times all three run back-to-back (not derived by summing the individual numbers) as the "combined" cost per FR-2, and reports the **median of 7 runs** per (metric x size) cell and per (combined x size) cell (7 chosen and stated in the file's docblock as: odd for a clean median, small enough to keep the suite fast, large enough that a single GC pause or scheduler hiccup does not dominate the reported number — the same reasoning `entityHighlightBenchmark.test.ts` uses for run-to-run stability, extended here to an explicit repeat-and-median rather than that file's own single-plus-manual-rerun approach); `console.log` prints a results table (metric/size/combined rows, ms) exactly as `entityHighlightBenchmark.test.ts` does, so a run's raw output is copy-pasteable evidence; the test's own assertions check only internal consistency — every reported timing is finite and >= 0, the combined-cost median is >= the largest individual metric's median at the same size minus a small timer-noise slack (since running three things back-to-back cannot be cheaper than the slowest one alone), and each metric produces a non-trivial result on the dialogue-bearing fixture (dialogue ratio > 0, at least one sentence found, at least one repeated word found) — no assertion sets a millisecond pass/fail threshold, per FR-6; run the file via `pnpm --filter getwrite-frontend exec vitest run proseDiagnosticsBenchmark --reporter=verbose` and record its actual console output in this task's Notes (paste the table).
**Depends on:** 1
**Estimate:** 3
**Notes:** Reason for 3: three small pure functions plus a repeat-and-median harness and copy-pasted real output, mirroring `entityHighlightBenchmark.test.ts`'s shape exactly (that file was itself sized similarly). Repetition methodology is this task's own call (median of 7 independent runs per cell, each run re-reading the same fixture text from memory — not from disk per run, since disk I/O is not part of what FR-1/FR-2 asks to measure): stated here for the record, not user-confirmed, and changeable if the actual run shows it unstable (if so, raise the repeat count and note the change here rather than silently rerunning once). The 100k-word cell's dialogue-ratio quote-scanning and sentence-split regexes are the ones most likely to show non-linear cost; watch for and report if either metric's 100k timing is disproportionately worse than a linear extrapolation from 1k/10k would predict — that observation, if it occurs, belongs in Task 3's finding, not silently dropped.
**Done:** [ ]
