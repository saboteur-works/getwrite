## Overview

A new document stores no status, but the sidebar's Status control shows one: the first entry of the project's status list, or "Draft" when the project has none. Filters read the stored value, so "Status is Draft" leaves out every document that only appears to be Draft (Measured). A project's statuses are a series, such as Outline, Draft, Revised, Polished, and the first step is not a default. Nothing in the app can change an existing project's statuses: they are set once, at creation, from the project type or a Scrivener import (Read, not run: `src/lib/models/project-creator.ts`; no route or screen writes `config.statuses`). This feature shows no status until the writer chooses one, offers only the statuses the project defines, lets the writer edit that list in Project Settings, and makes the sidebar, the Organizer and every filter agree on what a document's status is.

## Goals

- A document with no stored status reads as "No status" everywhere it is shown.
- A writer can choose a status, and can return a document to "No status".
- The statuses offered are exactly the project's own list. A project that defines none offers none.
- A writer can add, remove and reorder a project's statuses in Project Settings.
- The sidebar, the Organizer card, the Organizer filter, the query builder, smart folders, the goal filter and the status roll-up agree on every document's status.

## Non-goals

- Changing which statuses a built-in project type seeds, or editing a saved project type's statuses (the project type editor already does that). Blank and any other type that seeds no statuses start with none (Gate 1).
- A default status per project or per project type.
- Rewriting any stored file. No migration.
- Search, which needs no change (Read, not run): `components/SearchBar/SearchBar.tsx:65` and `SearchFilterPanel.tsx:87` already use the configured list and hide the status filter when it is empty; `DataView.tsx:269` has no fallback; the search route's `status` param is an exact match.
- The query builder's separate "Statuses" field (`resource.statuses`, Feature 86 FR-26), which already offers only the project's list (Gate 1). It is unchanged by this feature; only the `status` field's value list (FR-4) changes.

## User stories

- US-1: As a writer, I want to see no status on a new document until I give it one, so that the screen matches what my filters and counts see.
- US-2: As a writer whose project defines a series of statuses, I want to have none of them treated as a default, so that a document is only "Outline" when I said so.
- US-3: As a writer, I want to clear a document's status, so that I can undo a choice.
- US-4: As a writer in a project without statuses, I want to be offered no statuses, so that I only see statuses I set up.
- US-5: As a writer who already chose "Draft" in a project without statuses, I want to keep that choice visible, so that upgrading doesn't hide it.
- US-6: As a writer, I want to edit my project's statuses after creating it, so that a project from any type, Blank included, can use Status.

## Resolved questions

Owner decisions, 2026-11-02.

- RQ-1 (was OQ-1): a stored status not in the list is shown marked "(not in the current list)", as the Subtype control does. See FR-6.
- RQ-2 (was OQ-2): with no statuses defined, the control shows "No status" with a hint pointing to Project Settings, Metadata tab. See FR-7.
- RQ-3 (was OQ-3): the filter lists (query builder Status values, Organizer Status filter) offer the project's list only, never stored values found on documents. A document with an off-list status can be found by opening it, and changed or cleared there. See FR-4.
- RQ-4: nothing in the app could edit an existing project's statuses, so dropping the fallback would leave a Blank project unable to use Status. Add a Statuses editor to Project Settings in this feature. See FR-10 to FR-12.
- RQ-5 (Gate 3): the Data view "By status" message for a project with no statuses gains the same pointer as the sidebar hint, "Add them in Project Settings, Metadata tab." This reopens copy that `docs/features/status-rollup.md:15` records as confirmed. See FR-7.
- RQ-6 (Gate 3): with no statuses defined, the query builder's `status` field stays offered with an empty value list and no hint. A saved condition whose value is not in the list keeps working, and its value shows as "(unknown)", the label `ValuePicker.tsx:314` gives any off-list select value (the sidebar Subtype control instead says "(not in the current list)", F-6). See FR-4.
