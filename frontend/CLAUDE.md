# frontend/CLAUDE.md

Orientation for work under `frontend/` (`getwrite-frontend`: Next.js App Router, Redux Toolkit, TipTap, Zod, Storybook, all UI tests). All paths below are relative to `frontend/` unless they start with `docs/`, `specs/`, `electron/` or `cli/` (repo root). Repo-wide rules, standards and the glossary are in the root `CLAUDE.md`. Feature records are in `specs/features/<slug>.md` and `specs/features/<slug>/experiments.md`; prose docs in `docs/features/`.

## Commands (run from `frontend/`)

```bash
pnpm dev        # dev server
pnpm typecheck  # tsc --noEmit
pnpm lint       # ESLint
pnpm build      # next build
pnpm test       # Vitest (watch)
pnpm test:ci    # Vitest (single pass)
pnpm test:e2e   # Playwright; needs `pnpm storybook` on :6006
pnpm test:sharing-smoke  # sharing-gate refusal smoke; needs a built standalone server (pnpm build, then copy .next/static into .next/standalone/frontend/.next/static)
pnpm build:native        # Android static export (see "Native build")
```

From the repo root: `pnpm --filter getwrite-frontend exec vitest`.

## Testing and Storybook

- Unit, integration, component and a11y tests live in `tests/`; prefer TDD and extend an existing test file before creating one. E2E (`e2e/`, Playwright, Chromium only) runs against Storybook. Stories run `@storybook/addon-a11y` (global `"todo"`, opt-in per story with `parameters: { a11y: { test: "error" } }`); some `*.a11y.test.tsx` also run real `axe-core` through `tests/a11y/helpers/axe.ts` (`docs/standards/accessibility.md`).
- A component that starts requiring a React context needs a Storybook decorator: `.storybook/preview.tsx` wraps every story in `StaticSharingLimitsProvider` (default exempt; per-story `parameters.sharingLimits` overrides).
- Never invent component props: open the component source under `components/...` and its `*.stories.tsx` first; story names may not match prop names.
- `pnpm build:native` is known to fail at a type error in `stories/Start/CreateProjectModal.stories.tsx` (cause not established).

## Data layer (no database)

- Storage is `projects/` at the repo root (or `GETWRITE_PROJECTS_DIR`), one UUID folder per project:
  `project.json`; `resources/<uuid>/` (`content.txt` + `content.tiptap.json`); `folders/`; `meta/resource-<uuid>.meta.json` (sidecar); `meta/index/` (inverted index, backlinks, field values, mentions, diagnostics); `meta/queries/`; `meta/writing-log/YYYY-MM-DD.json` (one file per UTC day, not cleared by `reindex`); `meta/relationships.json`; `meta/entity-graph-positions.json`; `meta/templates/`; `revisions/<uuid>/v-<N>/`; `.trash/{resources,meta,revisions,folders}/` (soft delete; `meta/` holds trashed sidecars, `refs-<resourceId>.json` and `folder-<folderId>.json`).
- API routes (`app/api/`) read and write the filesystem directly. Main groups (not exhaustive): `projects`, `project/*` (id, delete, rename, tags, preferences, editor-config, metadata-schema, revision-settings, query, features, entity-mention-counts, entity-cooccurrence, entity-relationships, entity-graph-settings, entity-graph-positions, word-count-goal, mention-highlight-duration, writing-log, trash list/restore/purge), `project-resources`, `project-types`, `resource/*` (id, revision, upload, mentions, mentioned-in, sidecar, diagnostics, diagnostics-detail), `folder/[folder-id]/delete` (soft-delete cascade), `resource/[resource-id]/delete` (thin call to `deleteResourceCore`; no app caller found), `compile`, `export`, `global-noise-words`, `version-check`, `encryption` (lock state; unlock/lock/enable/export/resume; keyring is server-side on web and desktop because the model layer needs `node:fs`), `auth/[...all]` (better-auth catch-all; 404s when hosted auth inactive), `auth-status` (presentational `isHostedAuthActive()`), and `sharing/{pair,ready,limits}` (see Home-network sharing).
- **Project routes derive their root as `path.join(resolveProjectsDir(), projectId)` from a server-validated `projectId`** (`src/lib/models/project-path.ts`); they never accept a client-supplied `projectRoot`/`projectPath`. See `docs/standards/storage-context.md`, `docs/standards/security.md`.
- **Two schema boundaries, deliberately not unified**: `src/lib/models/schemas.ts` (Zod, gates all persisted data crossing the filesystem) and `src/lib/api/schemas.ts` (gates HTTP _response_ bodies, a projection of persisted data). `lib/api/schemas.ts` objects strip undeclared keys, so a new persisted field a client reads must be declared there too (e.g. `subtypes`, `appliesTo`).
- **Locks**: `src/lib/models/locks.ts` is a generic per-key async mutex; `meta-locks.ts` `withMetaLock` serializes metadata-affecting read-modify-write keyed by project root. The `*-core.ts` config setters (word-count goal, daily goal, mention highlight duration, entity graph settings) and `entity-relationships.ts` use `withMetaLock`; `project-features.ts` and `metadata-schema.ts` use `locks.ts`'s `acquireLock` instead. Whether every read-modify-write is locked is an open hypothesis, not established (POS note `note_746a516e`, recorded in `specs/product/getwrite.features.md`: unlocked read-modify-writes).

## State management

Redux Toolkit slices mirror filesystem state: `projectsSlice` (active project, config), `resourcesSlice` (resources and folders), `revisionsSlice`, `editorConfigSlice`, `querySlice`, `searchSlice`, `cryptoSlice` (workspace lock state only, never key material), `entityAliasTableSlice` (cache of the active project's `EntityAliasTable`, refetched on project load, resource load and a resolved sidecar save). State loads on mount via `GET /api/projects` and updates through explicit API calls; no optimistic or auto-sync layer.

## Code map (under `src/`)

### Patterns used throughout

- **Core + route + native backend**: transport-agnostic logic lives in `lib/models/<x>-core.ts`; the HTTP route (`app/api/.../route.ts`) and the native backend (`store/transport/native-<x>-backend.ts` + `.web-stub.ts`) both call it, so validation is identical on both paths. `project-root-resolver.ts` (`resolveProjectRoot()`, `Response`-free) is shared by every core.
- **`createTransport<T>(httpImpl, loadNative)`** (`store/transport/create-transport.ts`) is the only HTTP-vs-native collapse. It covers `store/`'s transports (revision, query, search, metadata-schema, feature-config, update-check, auth-status) and the `lib/api/*` modules. On native there is no HTTP round-trip. `.web-stub.ts` files are substituted for native backend imports by `next.config.mjs`'s `turbopack.resolveAlias` so no `node:*` code enters the web/desktop build. Exceptions: `lib/api/project-noise-words.ts` is HTTP-only (no native path); `lib/api/global-noise-words.ts` is a three-way split (web HTTP route, Electron `getDesktopBridge()` IPC to `userData/workspace.json`, native device file; no sync between the three; the Electron/web choice is made at call time inside `httpImpl`).
- **Reject vs degrade is per site and part of the contract.** `trash.ts`, `writing-log.ts`, `mention-highlight-duration.ts`, `word-count-goal.ts`, `encryption.ts` reject on failure (a degrade-to-empty would look like a real empty result). `mentions.ts`, `entity-alias-table.ts`, `prose-diagnostics.ts`, `tags.ts`, `entity-*` list reads degrade to a fallback; `entity-relationships.ts` also has `listEntityRelationshipsOrThrow` for the caller that must tell zero edges from a failed read. Do not change a site's contract when adding validation.
- **Response validation**: every HTTP transport method that parses a body validates it with a schema in `lib/api/schemas.ts` and reports a failure through `reportTransportValidationFailure(callSite, issues)` (`lib/api/transport-validation.ts`), which never receives or logs the raw body (it can hold decrypted prose on an encrypted project) and raises a deduplicated generic toast via `toastService.error` (`lib/toast-service.ts`). Covers projects, resources, project-types, entity-alias-table, entity-relationships, tags, mentions, entity-cooccurrence, entity-mention-counts, resource-excerpts, compile, export, encryption, editor-config, preferences. compile/export have separately declared (identical-shape) schemas on purpose. `resources.ts`'s `patchRevisionContent` validates, reports, and resolves `{ updatedAt: undefined }` on a malformed body (the save already succeeded) instead of throwing or inventing a client-clock timestamp; its interface and `useCanonicalAutosave.ts` treat `updatedAt` as optional. Native crosses no serialization boundary and is unaffected.
- **Fail closed on locked access**: `lib/models/locked-access.ts` exports `isLockedAccessError` (re-exports `ProjectLockedError`/`MissingProjectKeyError` from `crypto/adapter-selection.ts`). Catch sites must rethrow it rather than degrade to `{}`/`null`/`[]`/`false`/`0`. It deliberately excludes `ProjectMarkerFormatError` (corrupt marker = damaged project; propagates). `with-storage-context.ts` maps `ProjectLockedError` to HTTP 401 and `MissingProjectKeyError` to 409. See `docs/standards/failure-visibility.md`.
- **Optional-key clearing**: `updateSidecarCore` takes `clearKeys: string[]` because an `undefined`-valued key never survives `JSON.stringify` over HTTP. Allowlist `SIDECAR_CLEARABLE_KEYS` = `entityKind`, `aliases`, `wordCountGoal`, `resourceSubtype`; any other key throws `InvalidClearKeysCoreError` (400 at the sidecar route). It ignores a client-sent `wordCount`.
- **Config setters** (`word-count-goal-core.ts`, `mention-highlight-duration-core.ts`, `entity-graph-settings-core.ts`, `writing-log-core.ts`'s `setDailyWordGoalCore`) are read-modify-write under `withMetaLock`, touch only their own config key(s), and reject (not clamp) invalid numeric values. `entity-graph-settings-core.ts` writes two keys (`entityGraphConnectionTypes`, `entityGraphFocalHopRadius`) and drops unknown connection-type keys via `filterToKnownConnectionTypes` rather than rejecting them.

### Auth (`lib/auth/`)

Server-only hosted auth (better-auth + PostgreSQL; opt-in; ADR-020). `auth-config.ts` `isHostedAuthActive()` (true only when both `DATABASE_URL` and `BETTER_AUTH_SECRET` are set; single source of truth), `auth-server.ts` (lazy memoized `betterAuth`), `email.ts` (nodemailer), `signup-allowlist.ts` (`AUTH_SIGNUP_ALLOWLIST`, enforced in a `databaseHooks.user.create.before` hook, not `disableSignUp`), `session-guard.ts` (`shouldRedirectToLogin`), `verify-email-core.ts`. Client-safe: `auth-client.ts`, `use-auth-session.ts` (`useAuthSession()`, the combined hosted-active + authenticated signal UI components read). Desktop/local never runs any of it. `GETWRITE_ENABLE_DEV_IDENTITY` exercises tenant resolution locally.

### Home-network sharing (`lib/sharing/`, `proxy.ts`)

Desktop-only, off by default; gated by device pairing. Never runs with hosted auth. Plain HTTP only. See `docs/features/home-network-sharing.md`.

- `proxy.ts` (Next 16 proxy; no `middleware.ts`) calls `gate.ts` `runGate` for every request and does nothing else; no storage context there. `gate.ts` composes `sharing-env.ts` (`GETWRITE_SHARING` (only `"1"` is on), `GETWRITE_SHARING_DIR`, `GETWRITE_WINDOW_SECRET`, `GETWRITE_BIND`), `classify-request.ts` (pure: `off` / `window` / `confirmed:<id>` / `not-confirmed:<reason>`; window = `x-getwrite-window` header carrying the per-launch secret; paired device = `getwrite_device` cookie matching a stored hash), `host-allowlist.ts` (exact `Host` match against `localhost`, `127.0.0.1`, own-interface IPv4, `<hostname>.local`, computed per request; refusal is a plain-text 403, never a redirect), `same-origin.ts` (`Origin`, falling back to `Referer`, against `Host`; never `X-Forwarded-Host`), `credential-store.ts` (`device-credentials.json`, SHA-256 hashes only; missing = no devices; unreadable/invalid = `corrupt`, which refuses everything except `GET /api/sharing/ready`), `pairing-verify.ts` (`pairing-state.json`, wrong attempts per code, `MAX_WRONG_ATTEMPTS = 5`, under `file-lock.ts`), `device-name.ts`.
- The classification reaches route code only in the `x-getwrite-classification` request header, set after deleting any client copy (module state set in the proxy was measured not visible to routes). Peer address and `X-Forwarded-For` are never used for classification.
- Ungated exceptions (exact): `/pair` (`app/pair/page.tsx`, `PairingScreen`; refused under an unreadable store), `POST /api/sharing/pair` (not wrapped in `withStorageContext`, touches no project), `/_next/static/`, and `GET /api/sharing/ready?challenge=<64 hex>`. The ready route is consulted after the `Host` allowlist and before the store-corrupt condition; it reads no header, cookie, store or project; with `GETWRITE_READINESS_KEY` it returns `{ proof }` (`lib/readiness/readiness-proof.ts`, HMAC-SHA256 of the challenge), 400 for a malformed challenge, 404 without the key.
- `next.config.mjs` sets `experimental.proxyClientMaxBodySize` to `MAX_MEDIA_FILE_BYTES` + 1 MiB (adding `proxy.ts` brought in a 10 MiB default). The `pair` page is in `build-native-static.mjs`'s `EXCLUDED_APP_SUBPATHS`.
- **Paired-device limits**: five switches, `projectDeletion`, `unlocking` (resume follows it), `locking`, `encryptionChanges` (`enable` with an existing key, plaintext `export`), `permanentDeletion` (Trash purge/empty, revision delete); each restricted by default, global to all paired devices, effective next request. Creating the workspace passphrase (`enable` with a non-null passphrase) is always refused to a paired device (`PASSPHRASE_CREATION_REFUSAL_MESSAGE`). Window and sharing-off are never limited. State is `sharing-limits.json` (`{ version: 1, limits }`, `true` = restricted); `limits-store.ts` reads fresh every call, and a missing/unparseable/mistyped/other-version/unreadable file means all on. `limits-check.ts` (`decideLimit`, `checkLimit`, `refusalFor`, `limitsRoleFor`): window/off allowed; a missing or unparseable classification header is refused for every limited action without reading the file; a paired device is checked against the file. `limits-copy.ts` holds the 403 messages. Refusals are HTTP 403 `{ error, limit }` from `project/delete`, `project/[project-id]/trash/purge`, `resource/revision/[resource-id]` (`DELETE`) and `encryption` (`POST`, per action; the route reads the body from a clone). `GET /api/sharing/limits` is presentational (`{ role: "exempt" }` or `{ role: "paired", limits }`, never cached, accepts no change). Client: `store/sharing-limits-transport-service.ts`, `components/Sharing/SharingLimitsContext.tsx` (provider in `app/layout.tsx`), `limit-gate.ts`, `unlock-prompt-gate.ts`, `LimitReason.tsx`, `LimitSwitches.tsx`, `lib/api/limit-refusal.ts` (`LimitRefusalError`). `summarizeLimits` and `SHARING_LIMITS_POINTER` feed App Settings.
- Client: `components/Sharing/` (`SharingSettings`, `SharingStatus`, `PairingScreen`, `PairedDevices`, `sharing-copy.ts`, `pairing-page.ts`). The root layout mounts `DeviceNotPairedGuard` (wraps `window.fetch`; a 401 with `x-getwrite-gate: not-paired` goes to `/pair?reason=unpaired`, but never navigates when already on `/pair`; and `SharingLimitsProvider` makes no read there) except on native. Main-process side is in `electron/src/sharing/`. No HTTP route changes a limit, manages devices or toggles sharing; those are desktop IPC only.

### Native build

`pnpm build:native` (`GETWRITE_BUILD_TARGET=native`, `scripts/build-native-static.mjs`) assembles a shadow copy of `app/` in `.native-build/` with `app/api/**` and hosted-auth pages (`login`, `reset-password`, `verify-email`) removed (the real `app/` is never mutated) and runs `next build` with `output: "export"` (`next.config.mjs`; `standalone` otherwise); output is `out/`, which `android/capacitor.config.ts` `webDir` points at. `app/(app)/layout.tsx` skips the hosted-auth redirect on native. `.browserslistrc` pins Chrome >= 67. `getwrite-config` in `frontend/` is a generated, gitignored link (symlink on POSIX, junction on Windows) to the repo-root `getwrite-config/`, created by `scripts/ensure-config-link.mjs` (run by `postinstall`, `prebuild`, `pretypecheck` and the native build). Native runtime is selected by `NEXT_PUBLIC_GETWRITE_RUNTIME === "native"`.
